Frontend Structure

This page describes the frontend folder layout generated by Wails New and the conventions used throughout the project.

The structure is intentionally minimal and explicit.

Root Layout​

The frontend lives in a dedicated directory, typically:

frontend/
├─ index.html
├─ package.json
├─ vite.config.ts
├─ tailwind.config.ts
├─ postcss.config.cjs
└─ src/

This follows standard Vite conventions.

src/ Directory​

The src/ directory contains all application code:

src/
├─ main.ts
├─ App.svelte
├─ assets/
├─ components/
└─ lib/

main.ts​

  • Frontend entry point
  • Mounts the Svelte application
  • Initializes global styles

App.svelte​

  • Root Svelte component
  • Layout and top-level state
  • Entry point for UI composition

components/​

Reusable UI components:

  • Buttons
  • Modals
  • Layout elements

Components are kept small and focused.

assets/​

Static assets such as:

  • Images
  • Icons
  • Fonts

Handled directly by Vite.

lib/​

Shared utilities and helpers:

  • API wrappers
  • Shared logic
  • Constants

Avoid putting UI components here.

Styling​

Global styles are typically imported in main.ts.

Tailwind utilities are used directly in components.

Custom CSS should be kept minimal and scoped when possible.

Imports and Aliases​

Vite provides clean import paths.

Example:

import Button from "@/components/Button.svelte";

Aliases are defined in the Vite configuration.

Conventions​

  • One component per file
  • Explicit imports
  • No hidden magic
  • No auto-registration

The structure favors clarity over cleverness.

Extending the Structure​

You are free to:

  • Add routing
  • Add state management
  • Introduce feature folders

Wails New does not impose constraints beyond the initial layout.
